# 持仓、挂单与只读网页

## 记录的真相源

每个实际部署建立独立的 `config/portfolio.json`，行情规则和运行状态继续分文件保存。持仓台账包含版本、更新时间、比例分母、账户风险参数、positions、orders、updates；未知字段用 null，不用 0 代替未知。公开仓库只放空白或明确标为示例的台账，绝不发布用户实际持仓、挂单、任务 UUID、绝对路径或运行事件。

用户明确要求用对话维护记录时，网页不提供新增、编辑、删除、导入或“确认成交”入口，后台也不提供写入 API。用户在对话中报告或纠错后，AI 重新读台账，更新明确提供的字段，追加确认时间、来源和变更说明，用同目录临时文件、fsync 和原子替换保存，再从网页核对显示结果。不要仅在聊天回复里声称已记住。

建议不等于执行，触价不等于成交。新挂单只记录在 orders，只有用户确认成交后才更新 positions。部分成交只计已确认部分，同时明确剩余未成交量；撤单或改单要保留历史。涉及多个待成交订单且无法识别时，先厘清对应关系，不能猜是哪一笔。没有数量、金额或新均价时，不臆造加权成本。减仓后也不能简单用旧买入成本去推导实时账户占比。

仓位必须写清分母（整个账户或单币预算）与单位（1 成 = 10%），区分增加几成和加到几成。分别展示实际仓位、未成交买单计划、挂单全成交后的计划占用；这不等于实时可用余额，缺少账户余额时不能声称资金足够。未知或部分成交未给剩余量的挂单不可当作零占用。人民币成本与 USDT 行情不能直接比较；要标注汇率来源、时间及换算只是估算，历史换汇成本未知时不虚构精确盈亏。

事件消息引用实际台账路径，AI 开始研究时重新读取最新台账，不能用消息生成时的快照覆盖后续用户确认。市场事件只有只读研究权限；用户主动报成交或纠错是单独的台账更新指令。

## 现货建议

用户要求买卖信号时，先核验市场并重新读取台账，每次分别给出三个方向的判断：

- 建仓：适用于确认无持仓的币；已有持仓则标注不适用。核对未成交买单和可用预算，不能把未知仓位当作空仓。
- 加仓：适用于已有持仓的币；独立核对承接或突破证据、剩余风险预算和加仓后的集中度。没有条件时明确等待或暂不加仓。
- 减仓：适用于已有持仓的币；独立核对破位、突破失败、流动性恶化、风险预算或集中度超限，以及有证据的止盈情景。没有买入机会不等于可以放心持有，不能以“暂不加仓”代替减仓判断；证据不足也不要硬给卖出方案。

有证据支持操作时，给出方向、入场或减仓价格点/区间、报价时间与精度、必须满足的确认、每批增减几成及百分比、操作后该币总仓位、账户合计敞口、失效条件和适用期限。说明当前价格是否还在范围内。所有“几成”沿用用户确认的账户或单币预算分母；“减少全账户一成（10 个百分点）”与“卖出现有持币的 10%”不同，后者须另标为持币数量比例，不能冒充账户仓位或减仓后一成。

量化前标注持仓、成本、账户余额、风险承受和持有周期的确认时间。现有仓位与未成交买单可能占用同一份资金，不能重复分配；未成交卖单的预计回款也不能提前用于买入。给出价格到达失效位的估算损失，分开现有与新增风险；减仓则说明卖出部分的价格风险变化和剩余敞口。计算使用明确的基准、费用与滑点假设，失效位不保证成交或最大亏损。

信息不足时按方向列出真正影响判断的缺项，不编造适合用户的仓位比例、账户总额或风险预算。缺少现金余额可以阻止量化加仓，但不能阻止基于已验证事实的减仓风险提示、条件式观察价格和人工关注提醒；缺少账户分母时不得把持币数量比例伪装成全账户“几成”。同一缺项已询问仍未回答时简要注明待补充，不在每次回调重复追问。任何方案都不授权自动下单或修改台账。

## 网页架构

默认提供本机只读总览、监控规则与完整模板、触发记录、持仓和挂单、最近确认时间。页面显示实际运行状态：有新成交、等待新成交、状态未更新分别标注；旧行情保留事件时间，不能标成实时价。提交成功、任务收到消息和研究完成分开表示，合成测试不混入正式触发记录。

使用 Go 模板的 `dashboard --config config/dashboard.json --listen 127.0.0.1:8788`。dashboard.json 引用共享 portfolio_file 与各币 config_file；相对路径按登记文件所在目录解析。每个币种使用独立监控进程、规则配置和持久状态。网页仅统一读取这些文件，不另建行情连接或触发 AI。台账和各监控配置每秒重读，登记文件变更需要重启网页服务。

本模板单个服务每秒汇总一次状态，以 SSE 推送给所有页面；最多 100 个推送连接，每个连接只保留最新快照，慢连接不会堆积。页面隐藏时关闭推送，恢复后重连；客户端有重连退避，事件列表限制每币最近 30 条。不要让每个浏览器分别请求交易所或按行启动轮询。项目若要求确认并发方案，说明频率、限制、休眠/断流行为和本机访问范围后按已确认方案实施。

默认只绑定回环地址，只允许 GET/HEAD，校验 Host 与 Origin，不提供 CORS 和写操作。远程访问是新增暴露范围，需先确定认证与传输方案；不能为展示持仓随意绑定公网、开隧道或发布用户数据。

## 部署与网址交付（必须完成）

- 部署后从实际监听配置/启动日志取得运行 URL，并用 HTTP 请求和浏览器打开核验。不能只检查构建或进程，也不能把源码仓库、示例端口或无法访问的 URL 当作成果。
- 核对页面的价格更新时间、监控规则数、真实触发状态、持仓比例/成本币种和未成交订单；确认没有录入入口，写请求被拒绝，多个连接不会增加交易所请求。
- **最终回复必须给出用户可点击的实际运行网址**，说明访问范围（例如仅当前电脑）、是否已启动后台服务，以及停止/恢复方法所在文档。用户要求打开时直接打开并保留页面。
- 页面不可访问时先修复；外部条件确实阻塞则明确说尚未部署成功，不声称网址可用。本机服务在电脑休眠/断网时不保证行情覆盖，恢复后重新确认数据新鲜度。
